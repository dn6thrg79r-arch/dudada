# 관리자가 한 번 하는 클라우드 연결

PDF·필사를 Mac/iPad에서 공유하려면 저장 서버가 하나 필요합니다. 사용자에게는 아이디·비밀번호 두 칸만 보입니다. 관리자가 Supabase 프로젝트를 한 번 연결합니다. 실제 Supabase 프로젝트는 아직 이 작업에 연결되지 않았습니다.

## 1. Supabase 프로젝트 만들기

1. https://supabase.com 에 로그인합니다. **New project**를 선택하고 프로젝트를 만듭니다. 데이터베이스 비밀번호는 관리자만 보관하세요. 앱 사용자에게 줄 비밀번호와 별개입니다.
2. 프로젝트 왼쪽 **SQL Editor → New query**에서 저장소의 `supabase/setup.sql` 전체를 붙여넣고 **Run**을 누릅니다. 계정별 필사 테이블과 비공개 PDF 버킷, RLS 접근 규칙을 만듭니다.
3. **Authentication → Sign In / Providers → Email**에서 Email 로그인을 켜고 **Confirm email**을 끕니다. 이 앱은 입력한 아이디를 예약된 `.invalid` 주소로 변환해 인증에 사용하므로 이메일 수신/인증을 요구하지 않습니다. 이메일 인증을 켜 두면 신규 가입이 완료되지 않습니다.
4. **Authentication → Settings**의 비밀번호 최소 길이를 8자 이상으로 설정합니다. 이메일 가입이 허용되어 있어야 합니다. 이메일 링크·소셜 로그인은 필요 없습니다.

같은 아이디는 대소문자/유니코드 표기를 정리해 같은 계정으로 처리합니다. 한글·영문·숫자·밑줄·하이픈 3~32자입니다. 존재하는 아이디의 비밀번호가 다르면 가입을 거절하며 기존 계정을 덮어쓰지 않습니다. 복구용 이메일이 없으므로 사용자가 비밀번호를 잊으면 직접 복구할 수 없습니다. 관리자도 사용자에게 비밀번호 값을 요청하지 마세요.

## 2. GitHub에 공개 연결값 등록하기

Supabase **Project Settings → API / API Keys**에서 **Project URL**과 **publishable key**를 찾습니다.

GitHub 저장소 **Settings → Secrets and variables → Actions → Variables → New repository variable**에서 다음 두 개를 추가합니다.

- `NEXT_PUBLIC_SUPABASE_URL`: Project URL (`https://프로젝트식별자.supabase.co`)
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: publishable key (`sb_publishable_...`)

이 두 값은 브라우저 앱에 포함되는 공개 연결값입니다. **secret key, service_role key, DB 비밀번호는 넣지 마세요.** 계정 데이터 보호는 공개 키를 숨기는 방식이 아니라 서버의 Auth와 RLS로 처리합니다. 프로젝트 보안 규칙을 비활성화하지 마세요.

## 3. 배포하기

GitHub **Actions → Deploy GitHub Pages → Run workflow**에서 `feat/pdf-transcription`을 실행합니다. 배포 후 공부방에는 아이디·비밀번호 화면이 나타납니다. 새로운 아이디로 들어가 PDF를 한 번 선택하면 서버에 저장됩니다. 같은 아이디/비밀번호로 iPad에서 들어가면 PDF와 필사를 자동으로 불러옵니다.

프로젝트 설정이 없으면 메인 화면에서 로그인/서버 저장을 사용할 수 없다고 명확히 안내합니다. 로그인 화면만 꾸며 놓고 계정이 저장된 것처럼 처리하지 않습니다. 기존 운영 사이트는 새 버전을 배포하기 전까지 바뀌지 않습니다.

로컬 `.env.local`에도 같은 두 공개 값을 지정할 수 있습니다. 이 파일은 Git 커밋에서 제외됩니다.

## 이전 필사 옮기기

로그인 후 **설정 → 이전 브라우저 필사 가져오기**를 누르면 그 브라우저의 이전 필사를 해당 계정으로 복사합니다. 다른 계정으로 자동 배정하지 않습니다. 이전 버전에서는 PDF를 보관하지 않았으므로 원본은 한 번 다시 선택해야 합니다. 원래 브라우저 자료는 지우지 않습니다. 기존 브라우저 전용 화면은 `/local/`에 남겨 두었습니다. 이 경로는 기존 로컬 자료만 다루며 클라우드 계정 자료를 표시하지 않습니다.

## 저장 동작과 한계

- PDF는 계정별 **비공개** Storage에 저장합니다. 다른 사용자는 서버 정책으로 접근할 수 없습니다. 공개 PDF URL을 만들지 않습니다.
- 큰 PDF는 10MB 이하 조각으로 올립니다. 모든 조각을 올린 다음에만 저장 완료 정보를 기록합니다. 저장 실패 시 이전에 저장된 PDF는 그대로 둡니다. 100MB 이상 파일도 브라우저/계정 용량 범위에서 지원하며 앱의 512MB 제한은 유지합니다.
- 암호가 걸린 PDF는 암호화된 원본 그대로 저장합니다. PDF 암호는 서버에 저장하지 않습니다. 다음에 열 때 PDF 암호 입력이 필요할 수 있습니다.
- 페이지별 필사와 설정은 계정별 DB에 저장합니다. 연속 입력은 묶어서 보내되 저장이 끝나기 전에는 저장 완료로 처리하지 않습니다. 이전의 입력 중 깜빡임 방지를 유지합니다.
- 두 기기에서 같은 자료를 동시에 수정하면 변경 충돌을 감지해 덮어쓰기를 막습니다. 현재 글을 TXT로 내보낸 뒤 자료를 다시 불러오세요. 실시간 공동 편집이나 두 문서 자동 병합은 제공하지 않습니다.
- 인터넷이 끊기면 클라우드 저장에 실패했다고 표시합니다. 미동기화 필사는 계정별로 이 브라우저의 IndexedDB에 임시 보관하고, 연결이 돌아와 같은 계정으로 자료를 불러오면 다시 저장합니다. 다른 기기의 변경과 겹치면 별도 “복구본”으로 보존합니다. 임시 저장도 차단되거나 브라우저 데이터를 지우면 복구할 수 없으므로 중요한 글은 TXT로 보관하세요. 서버 연결 없이 새 기기에서 로그인/원문 복원은 할 수 없습니다.
- Supabase 무료 플랜의 총 저장량/트래픽/휴면 정책이 적용됩니다. 조각 업로드는 파일당 제한을 줄이는 방법이며 총 용량을 늘려 주지 않습니다. 관리자 콘솔에서 사용량을 확인하세요.
- 저장된 PDF는 설정에서 삭제할 수 있으며 필사는 남습니다. 업로드 중 브라우저 강제 종료 등으로 남은 미참조 조각은 관리자 Storage에서 정리할 수 있습니다. 정상 실패의 조각은 앱이 정리를 시도합니다.
- 기존 브라우저 저장소와 계정 자료를 자동으로 혼합하지 않습니다. 같은 브라우저에서 로그아웃하면 화면과 PDF를 닫고, 다른 계정으로 로그인할 때 다시 해당 계정 자료만 가져옵니다.

## 실제 연결 후 확인할 것

1. 새 아이디로 가입 → PDF 업로드 → 필사 → 저장 완료 확인.
2. 다른 브라우저/iPad에서 같은 계정 로그인 → PDF/필사 복원.
3. 같은 아이디에 틀린 비밀번호 → 로그인 실패, 원래 자료 유지.
4. 다른 아이디로 가입 → 이전 계정 자료가 보이지 않음.
5. Supabase SQL Editor의 RLS 및 Storage 비공개 설정 확인. 서로 다른 두 실제 계정의 토큰으로 다른 계정의 DB/Storage 읽기·쓰기 요청이 거절되는지 검증.
6. 저장 공간 부족/인터넷 끊김/동시 수정 충돌에서 저장 실패가 표시되고 현재 글을 내보낼 수 있는지 확인.

실제 Supabase 서비스의 인증·정책·스토리지 검증을 마치기 전에는 운영 준비 완료로 판단하지 마세요. 테스트용 HTTP 응답을 이용한 자동 검사는 실제 서버 RLS 검증을 대신하지 않습니다.
