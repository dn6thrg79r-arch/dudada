# 두다다 공부방 · PDF 필사 공부방

**원문을 읽고, 내 속도로 옮겨 적는 집중형 공부방**입니다.

왼쪽에는 실제 PDF 원본, 오른쪽에는 빈 필사 문서를 보여줍니다. 신문형 PDF의 단·사진·제목·표는 원래 모양 그대로 유지됩니다. 속도·정확도·점수·정답 비교·자동 문장 진행은 없습니다. 계정이나 유료 API, 별도 데이터베이스도 필요 없습니다.

## 처음 실행하기 (Mac)

1. [Node.js 공식 사이트](https://nodejs.org/ko)에서 **24 LTS**를 설치합니다.
2. 저장소의 `feat/pdf-transcription` 브랜치를 ZIP으로 다운로드하고 압축을 풉니다.
3. Mac의 터미널을 열고 `cd `를 입력한 뒤 압축을 푼 폴더를 드래그하고 Enter를 누릅니다.
4. 다음 명령을 한 줄씩 실행합니다.

```sh
npm ci
npm run dev
```

5. 브라우저에서 `http://localhost:3000`을 엽니다. 종료는 터미널에서 Control+C를 누릅니다.

다음부터는 같은 폴더에서 `npm run dev`만 실행하면 됩니다. 배포와 같은 방식으로 실행하려면:

```sh
npm run build
npm start
```

PDF.js worker·한글 CMap·폰트·WASM은 `npm ci` 과정에서 `public/pdfjs`로 복사됩니다. CDN에 의존하지 않고 PDF.js와 worker 버전이 일치합니다. 관련 파일이 없다면 `npm run postinstall`을 실행하세요. 개발 서버의 테스트 주소 `127.0.0.1`은 `next.config.ts`에 명시적으로 허용했습니다.

## 사용하는 방법

1. **PDF 불러오기**를 누르거나 첫 화면에 PDF를 끌어 놓습니다. 암호가 있으면 암호를 입력하고 다시 엽니다.
2. 왼쪽의 원본을 보며 오른쪽의 빈 문서에 자유롭게 씁니다. Enter·빈 줄·띄어쓰기·선택·복사·붙여넣기가 모두 가능합니다.
3. **125% / 150% / 200%** 등을 선택해 PDF를 확대하거나 **너비 맞춤** 버튼을 누릅니다. 마우스 휠과 트랙패드로 확대된 페이지를 자유롭게 스크롤할 수 있습니다.
4. 가운데 경계선을 드래그해 기본 **55% / 45%** 비율을 조정합니다. 경계선에 키보드 포커스를 두고 좌우 방향키를 눌러도 조정됩니다.
5. 이전/다음 버튼 또는 페이지 선택으로 이동합니다. 각 페이지의 필사는 따로 저장됩니다. **설정 → PDF 페이지에 맞춰 필사 전환**을 끄면 다른 원문 페이지를 참고해도 필사 페이지가 그대로 유지됩니다. 이때 편집기 상단에서 작성할 페이지를 직접 고를 수 있습니다.
6. 오른쪽 위 **내보내기 → 모든 페이지 TXT / Markdown**으로 모든 필사를 페이지 순서대로 내려받습니다. 원문의 추출 글자가 아닌, 사용자가 작성한 필사만 내보냅니다.
7. 다시 접속하면 마지막 필사와 설정을 복원합니다. PDF 원본은 저장하지 않으므로 **원본 PDF 다시 연결**로 같은 파일을 선택하세요. 파일의 PDF 식별자·크기·페이지 수를 확인해 잘못된 연결을 막습니다. PDF 내부 식별자가 같아도 내용이 조작된 파일까지 보증하는 암호학적 검증은 아닙니다.
8. 폴더 아이콘의 **내 필사 자료**에서 다른 자료를 다시 엽니다. 새로운 PDF를 불러와도 기존 필사는 남습니다.

### 글쓰기와 설정

- 기본 **19px / 줄 간격 1.8**, 넉넉한 여백, 자동 줄바꿈.
- 설정에서 글씨 크기와 다크 모드를 바꿉니다.
- 맞춤법 검사·자동 교정·자동 대문자화는 기본적으로 끕니다.
- 편집기는 일반 텍스트 문서입니다. Cmd+Z / Cmd+Shift+Z, 전체 선택 등 브라우저의 기본 편집 기능을 사용합니다. Markdown은 문법 그대로 작성하고 `.md`로 내보냅니다. 서식 도구가 있는 워드 프로세서는 아닙니다.
- 입력·확대·저장·분할 조정으로 편집기를 다시 마운트하지 않습니다. 명시적인 자료/필사 페이지 전환 또는 파일 가져오기 때만 내용을 교체합니다. 따라서 같은 페이지의 커서·선택·스크롤·실행 취소가 유지됩니다. 페이지를 바꾸면 해당 페이지의 브라우저 실행 취소 이력은 새로 시작합니다.
- 편집기 아래 **필사 파일 불러오기**로 UTF-8 TXT/Markdown을 현재 페이지에 불러옵니다. 현재 글이 있으면 교체 여부를 확인합니다. 여러 페이지 내보내기 파일을 가져오면 파일 전체를 현재 페이지에 넣습니다. 페이지 제목을 해석해 자동 분배하지 않습니다.

## 저장과 개인정보

IndexedDB에 자료 이름, 원본 파일 식별 정보, 페이지별 필사, 마지막 PDF/편집 페이지, 페이지 연결 설정, 확대율, 분할 비율, 글씨 크기, 마지막 수정 날짜를 저장합니다. 다크 모드 선호는 localStorage에 저장합니다.

- **PDF 원본과 PDF 암호는 영구 저장하지 않습니다.** 서버로 PDF·필사 내용을 전송하는 API, AI 요청, 분석 서비스가 없습니다.
- 저장은 순서대로 처리하고 최신 쓰기가 실제로 완료되어야 **자동 저장됨**이라고 표시합니다. 실패하면 오류를 표시하고 **저장 재시도 / TXT 내보내기**를 제공합니다. 아직 저장되지 않은 상태로 탭을 닫으려 하면 브라우저 경고를 요청합니다.
- 탭을 닫기 전 저장 상태를 확인하세요. OS 강제 종료·브라우저 충돌 직전의 미완료 쓰기까지 보장할 수는 없습니다.
- 같은 브라우저·같은 사이트 주소에서만 이어 쓸 수 있습니다. Mac/iPad 간 자동 동기화는 없습니다. 브라우저 데이터 삭제·비공개 모드·저장 공간 부족에 대비해 중요한 필사는 내보내기로 보관하세요.
- 이전 타자연습 버전의 `materials` 저장소는 삭제하지 않습니다. 해당 모드에서 실제 입력했던 글은 페이지별 필사로 복원하고, 기존의 추출·편집 원문은 **설정 → 이전 버전 편집 글 내려받기**로 별도 보관할 수 있습니다. 이전 게임 점수는 현재 UI에 표시하지 않습니다.
- PDF/TXT, `.env`, 빌드·브라우저 테스트 산출물은 Git 커밋에서 제외합니다. 테스트용 PDF는 사용자 문서가 아닌 합성 문서입니다.

## 화면과 PDF 처리

- Mac/데스크톱·iPad 가로: 좌우 분할, 독립 스크롤.
- iPad 세로(601~900px): 상하 분할, 독립 스크롤.
- iPhone(600px 이하): **PDF 보기 / 필사하기** 탭. 전환 시 편집기 DOM은 유지합니다.
- 한 번에 현재 PDF 한 페이지만 렌더링합니다. 페이지 이동으로 화면을 바꾸며, 페이지 사이를 연속으로 스크롤하는 다중 페이지 뷰어는 아닙니다. 한 페이지 내부에서는 가로/세로 스크롤이 가능합니다.
- 캔버스 픽셀 수를 1,200만 이내로 제한하고, 이전 캔버스와 페이지 렌더링 자원을 정리합니다. 큰 원문을 확대할 때 기기에 따라 해상도를 낮춰 메모리를 보호합니다.
- 100MB 이상 PDF도 열 수 있으며 진행률을 표시합니다. 512MB 초과는 보호를 위해 거절합니다. 브라우저/PDF.js가 원본 전체 바이트를 읽을 수 있으므로 필요한 페이지 렌더링만으로 파일 읽기 메모리를 완전히 없애지는 않습니다.
- 메모리가 부족하면 다른 탭을 닫거나 PDF를 작은 묶음으로 나눠 다시 시도하세요. OS가 브라우저 탭 자체를 종료한 경우는 앱에서 복구를 보장하지 못합니다.
- 스캔·이미지형 PDF도 원본 그대로 보며 필사할 수 있습니다. 텍스트 추출과 OCR은 필요하지 않아 현재 사용 흐름에서 제거했습니다.

## 테스트

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e -- --project=chromium
```

시스템 `/usr/bin/chromium`이 있으면 사용합니다. 다른 OS에서는 `npx playwright install chromium`으로 브라우저를 설치하면 됩니다. 별도 실행 파일은 `CHROMIUM_PATH`로 지정할 수 있습니다. E2E는 기본적으로 프로덕션 서버를 시작합니다. 이미 3000 포트의 서버가 있으면 재사용합니다.

```sh
# 개발 서버에서 검사
E2E_DEV=1 npm run test:e2e -- --project=chromium
# 별도 포트에서 프로덕션 서버 검사
E2E_PORT=3100 npm run test:e2e -- --project=chromium
# WebKit/iPad 화면 모사 (브라우저 설치 가능한 환경)
npx playwright install --with-deps webkit
npm run test:e2e -- --project=webkit
```

Vitest는 페이지 연결/고정, 글 보존, TXT/Markdown 내보내기, 파일 재연결, 저장 순서·실패·재시도를 검사합니다. E2E는 원본 렌더링, 빈 편집기, 자유 입력·한글 조합 이벤트·네이티브 undo/redo, 확대/스크롤 시 편집기 유지, 페이지별 자동 저장과 새로고침 복원, 재연결, 내보내기/가져오기, 분할 비율/글씨 크기, 저장 실패, 스캔/암호/손상/100MB 이상 PDF, 반응형, 이전 저장소 마이그레이션을 확인합니다.

실제 연세의료원소식 파일은 제공받지 않았습니다. 실제 macOS Safari/iPad Safari와 외장 키보드 두벌식 입력은 직접 확인하지 못했습니다. 합성 IME 이벤트와 화면 크기 모사는 실기기 검증을 대신하지 않습니다.

## Vercel 배포

1. Vercel에 GitHub 계정으로 로그인하고 **Add New → Project**에서 이 저장소를 선택합니다.
2. 코드가 있는 `feat/pdf-transcription` 브랜치를 선택합니다. Framework는 **Next.js**, Root Directory는 저장소 루트, Node.js는 **24.x**입니다.
3. 기본 설치·빌드 명령을 유지하고 Deploy를 누릅니다. API 키나 별도 DB 설정은 필요 없습니다.
4. 발급된 HTTPS 주소를 Mac/iPad에서 엽니다. iPad 공유 메뉴 → **홈 화면에 추가**도 가능합니다.

앱 수정 작업에서 Vercel 배포나 클라우드 환경 게시를 자동으로 수행하지 않습니다.

## 코드 구조

- `app/study-app.tsx`: 분할 화면·PDF 연결·필사 자료·설정·내보내기
- `app/pdf-preview.tsx`: 현재 원본 페이지의 크기 대응 렌더링·메모리 관리
- `app/transcription-editor.tsx`: 브라우저 기본 편집/IME를 보존하는 비제어 textarea
- `lib/pdf.ts`: 브라우저 전용 PDF.js 동적 로딩과 오류 안내
- `lib/notebook.ts`: 필사 모델·페이지 전환·내보내기·저장 큐
- `lib/storage.ts`: IndexedDB와 이전 자료 보존/이관
