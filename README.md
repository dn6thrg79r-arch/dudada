# 두다다 공부방 · PDF 필사 공부방

**PDF 원문을 읽으며, 내 속도로 옮겨 적는 공부방**입니다. 왼쪽은 원본 PDF, 오른쪽은 자유 필사 편집기입니다. 속도·정확도·점수·정답 비교는 없습니다.

이제 아이디·비밀번호로 로그인하고 **계정별 PDF와 필사를 Mac/iPad에서 공유하는 클라우드 기능**을 연결합니다. 실제 서비스 사용에는 관리자가 Supabase 프로젝트를 한 번 연결해야 합니다. 이 저장소만 배포해 서버가 자동으로 생기지는 않습니다.

## 먼저 할 일: 저장 서버 연결

**[관리자용 클라우드 연결 안내](docs/CLOUD_SETUP.md)**를 따라 주세요.

1. [Supabase](https://supabase.com) 프로젝트를 만듭니다.
2. SQL Editor에서 [계정별 접근 규칙·테이블 설정](supabase/setup.sql)을 실행합니다. Email 로그인을 켜고 이메일 확인은 끕니다.
3. Supabase의 **Project URL / publishable key** 두 공개 값을 GitHub **Settings → Secrets and variables → Actions → Variables**에 등록합니다.
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
4. GitHub **Actions → Deploy GitHub Pages → Run workflow → feat/pdf-transcription**으로 배포합니다.

**secret key, service_role key, DB 비밀번호는 공개 변수나 브라우저에 넣지 마세요.** 프로젝트 연결값이 없으면 Pages 배포는 중단하며, 미설정 상태의 로그인 화면에서도 사용 불가 사유를 안내합니다. 기존 운영 사이트는 새 배포 전까지 그대로입니다.

배포 주소: `https://dn6thrg79r-arch.github.io/dudada/` (실제 배포 성공 후 사용).

GitHub Pages 최초 설정이 필요하면 저장소 **Settings → General → Default branch**를 `feat/pdf-transcription`으로 지정하고, **Settings → Pages → Source**를 **GitHub Actions**로 설정합니다. `github-pages` 환경의 허용 브랜치에도 `feat/pdf-transcription`을 추가합니다. 모든 브랜치를 무제한 허용할 필요는 없습니다.

## 로그인과 사용

- 화면에는 **아이디 / 비밀번호** 두 칸과 **들어가기**만 있습니다.
- 처음 쓰는 아이디면 새 계정을 만듭니다. 같은 아이디·같은 비밀번호로 계속 로그인합니다.
- 같은 아이디에 다른 비밀번호는 로그인 실패로 처리하며 기존 계정을 덮어쓰지 않습니다. 다른 아이디는 별도 자료 공간을 만듭니다.
- 아이디는 한글·영문·숫자·밑줄·하이픈 3~32자입니다. 대소문자와 유니코드 표기를 정리합니다. 비밀번호는 4~128자입니다.
- 이메일을 받지 않으므로 앱에서 비밀번호 재설정 메일을 보낼 수 없습니다. 비밀번호를 기억해 두세요.
- 로그인 후 PDF를 한 번 선택하면 계정의 비공개 저장소에 업로드합니다. 업로드 진행률을 보여 줍니다.
- 같은 계정으로 다른 기기에서 로그인하거나 다시 접속하면 마지막 자료의 PDF와 필사를 자동으로 불러옵니다.
- PDF 암호는 저장하지 않습니다. 암호가 있는 파일은 다시 열 때 PDF 암호를 입력해야 합니다.
- 폴더 아이콘에서 다른 자료를 열고, 설정에서 저장된 PDF만 삭제할 수 있습니다. PDF를 삭제해도 필사 글은 남습니다.

## 필사 화면

- 기본 **PDF 55% / 필사 45%**, 가운데 경계선을 드래그하거나 키보드 방향키로 조정합니다.
- PDF 원본의 단·사진·표·제목을 그대로 표시합니다. 125%·150%·200% 확대와 너비 맞춤을 제공합니다.
- 한 번에 현재 PDF 한 페이지만 렌더링합니다. 이전/다음과 페이지 선택으로 이동하며, 페이지 안에서는 마우스·트랙패드로 가로/세로 스크롤합니다.
- 두 영역은 독립적으로 스크롤합니다. PDF를 확대해도 편집기 DOM·입력 포커스·글은 유지됩니다.
- 편집기는 기본 19px / 줄 간격 1.8입니다. Enter·공백·문단·선택·복사·붙여넣기, Cmd+Z / Cmd+Shift+Z를 그대로 사용합니다.
- 맞춤법 검사·자동 교정·자동 대문자화를 끕니다. 한글 조합 중에는 버튼을 흐리게 바꾸지 않으며 정상 저장 표시의 크기도 고정합니다.
- 페이지별 필사가 따로 저장됩니다. **설정 → PDF 페이지에 맞춰 필사 전환**을 끄면 다른 원문 페이지를 참고하며 같은 필사를 계속 쓸 수 있습니다.
- **내보내기 → 모든 페이지 TXT / Markdown**으로 보관합니다. UTF-8 TXT/MD를 현재 필사 페이지에 불러올 수도 있습니다.
- 글씨 크기·다크 모드 지원. iPad 가로는 좌우, 세로는 상하, iPhone은 PDF/필사 탭으로 전환합니다.

## 저장과 개인정보

**클라우드 계정 모드**는 사용자가 요청한 PDF·필사를 Supabase로 전송합니다. PDF는 공개 URL이 아닌 비공개 버킷에, 필사는 계정별 RLS 적용 DB에 저장합니다. 관리자 설정 SQL에서 다른 계정의 접근을 제한합니다. AI·OCR·광고 분석 API로 자료를 보내지 않습니다.

- 서버 로그인은 Supabase Auth가 처리합니다. 앱이 비밀번호 원문을 별도 저장하거나 PDF에 넣지 않습니다. 로그인 세션 토큰은 SDK가 브라우저에 유지합니다.
- PDF는 10MB 조각으로 업로드하고 모든 조각이 성공한 뒤 저장 완료 정보를 기록합니다. 100MB 이상도 기기/서비스 용량 범위에서 지원하며 512MB 초과는 메모리 보호를 위해 거절합니다.
- PDF.js가 원본 전체 바이트를 읽을 수 있습니다. 렌더링은 한 페이지만 하며 캔버스는 1,200만 픽셀 이내로 제한합니다. 메모리가 부족하면 다른 탭을 닫거나 PDF를 나눠 사용하세요.
- 연속 입력은 최신 글을 묶어 저장합니다. 서버 쓰기가 끝나야 실제 저장 완료로 표시합니다. 오류 때는 명확히 알리고 현재 글을 내보낼 수 있습니다.
- 미동기화 글은 이 브라우저의 계정별 IndexedDB에 임시 보관하고 연결 복구 후 같은 계정에서 다시 저장합니다. 다른 기기의 변경과 충돌하면 별도 복구본으로 보존합니다. 캐시를 지우거나 저장소가 차단되면 복구되지 않으므로 중요한 글은 TXT로 보관하세요.
- 두 기기에서 같은 자료를 동시에 수정하면 충돌을 감지해 덮어쓰기를 막습니다. 실시간 공동 편집/자동 문단 병합은 지원하지 않습니다.
- Supabase 무료 플랜에도 총 저장량·다운로드 트래픽·휴면 제한이 있습니다. 조각 업로드는 총 용량을 늘리지 않습니다. 관리자 콘솔에서 사용량을 확인하세요.

## 기존 자료 보존

기존 브라우저 전용 자료를 삭제하거나 임의 계정에 넘기지 않습니다. 로그인 후 **설정 → 이전 브라우저 필사 가져오기**로 해당 계정에 복사할 수 있습니다. 이전 버전은 PDF 원본을 저장하지 않았으므로 원본은 한 번 다시 선택해 주세요.

이전 브라우저 전용 화면은 `/local/`에 보존했습니다. 이 경로는 기존 로컬 자료만 표시하며 클라우드 계정 자료는 표시하지 않습니다. 로컬 모드는 계정 로그인·기기 간 공유가 없고 원본 PDF도 서버에 저장하지 않습니다. 이전 `materials` 저장소와 편집 원문 보존/다운로드 기능도 유지합니다.

## Mac에서 개발 실행

Node.js **24 LTS**를 설치하고 저장소 폴더에서 실행합니다.

```sh
npm ci
npm run dev
# http://localhost:3000
```

프로젝트 루트의 `.env.local`에 위의 공개 연결값 2개를 지정하면 로그인·클라우드 모드가 연결됩니다. `.env.local`은 커밋에서 제외됩니다. 미설정이면 메인 화면은 설정 필요 안내를 표시합니다. 기존 로컬 모드는 `http://localhost:3000/local/`에서 확인할 수 있습니다.

일반 프로덕션 빌드는 `npm run build` 후 `npm start`입니다. Vercel에서도 같은 공개 환경변수 2개를 등록하고 Next.js 기본 설정으로 배포할 수 있습니다. Pages 전용 확인은:

```sh
npm run build:pages
npm run preview:pages
# http://127.0.0.1:3102/dudada/
```

PDF.js worker·한글 CMap·폰트·WASM은 `npm ci`에서 같은 사이트의 `public/pdfjs`로 복사합니다. worker 문제가 있으면 `npm run postinstall`로 복구합니다.

## 테스트와 현재 검증 범위

```sh
npm run lint
npm run typecheck
npm test
npm run build:pages
npm run test:pages
npm run test:cloud
```

- `test:pages`: 기존 브라우저 전용 기능 검사. `/local/`에서 PDF·필사·저장·복원·IME·화면 안정성을 검증합니다. 기본 실행에서는 클라우드 전용 테스트를 명시적으로 건너뜁니다.
- `test:cloud`: **테스트 전용 가짜 공개 URL/키와 HTTP 응답**을 사용해 별도의 Pages 빌드를 만들고 로그인·가입·틀린 비밀번호·독립 브라우저 복원·계정 분리·업로드 실패·미동기화 복구를 검사합니다. 실제 사용자 비밀번호나 프로젝트 키를 쓰지 않습니다. 이 명령의 `out/` 산출물을 배포하지 마세요. 배포 워크플로는 실제 연결값으로 새로 빌드합니다.
- Chromium이 없으면 `npx playwright install chromium`을 먼저 실행합니다. 실제 macOS/iPad의 Safari 및 외장 두벌식 키보드는 직접 검증하지 못했습니다.
- **실제 Supabase 프로젝트는 아직 연결되지 않았습니다.** 테스트용 HTTP 응답 검사와 서버 RLS·실제 계정·실제 기기 간 동기화 검증은 별개입니다. 관리자가 [클라우드 연결 안내](docs/CLOUD_SETUP.md)의 설정과 실제 계정 간 접근 차단 검증을 끝내야 운영에 사용할 수 있습니다.

소스 구조: `app/account-app.tsx`(로그인), `app/study-app.tsx`(공부방), `lib/cloud-repository.ts`(계정별 저장), `lib/cloud-cache.ts`(미동기화 임시 보관), `supabase/setup.sql`(서버 규칙), `lib/storage.ts`(기존 로컬 자료).

### 이번 변경의 검증 (2026-11-10)

린트·타입 검사·Pages 정적 빌드 통과. 단위 테스트 13개, 기존 브라우저 기능 E2E 8개, 테스트 서버 응답을 이용한 클라우드 계약 E2E 4개가 통과했습니다. 클라우드 계약 검사는 서로 독립된 브라우저의 동일 계정 복원, 틀린 비밀번호, 계정 분리, 저장 실패, 임시 필사 복구, 101MB PDF의 11개 조각 저장·복원을 포함합니다. 일반 E2E 실행에서는 클라우드 전용 4개를 명시적으로 건너뛰고 `test:cloud`에서 별도로 실행합니다. 프로덕션 의존성 감사에서 알려진 취약점 0개였습니다. 실제 Supabase 계정·DB/Storage 정책과 실제 iPad Safari 동기화는 프로젝트 연결 후 검증해야 하며, 현재는 미검증입니다.

### 4자 이상 암호 지원

공부방의 입력 최소 길이를 4자로 조정했습니다. Supabase의 서버 최소 길이(6자)에 맞추기 위해 4~7자 입력은 고정된 아이디별 PBKDF2 변환 후 인증에 사용하고, 기존 8자 이상 비밀번호는 그대로 유지합니다. 세부 호환성·한계는 [연결 안내](docs/CLOUD_SETUP.md#4자-이상-비밀번호-지원)를 참고하세요. Supabase 최소 길이를 4자로 낮추려 할 필요는 없습니다.

4자 암호 변경 후 린트·타입 검사·Pages 빌드, 단위 테스트 16개, 클라우드 계약 E2E 5개가 통과했습니다. 새 검사는 4자 가입/재로그인·3자 거절·틀린 4자 암호 거절·기존 8자 이상 계정 호환을 포함합니다. 실제 Supabase 프로젝트에서의 가입 검증은 별도입니다.

## 전체화면으로 집중하기

자료를 연 뒤 상단 **전체화면**을 누르면 상단 메뉴·파일 도구줄·영역 제목·편집기 하단을 숨기고 PDF와 필사 영역만 남깁니다. 가운데 분할 조정과 각 영역의 스크롤, 자동 저장은 유지됩니다. 우측 상단의 작은 나가기 버튼 또는 Esc로 돌아옵니다. 한글 조합 중 Esc는 앱의 화면 종료 단축키로 가로채지 않습니다.

지원 브라우저에서는 실제 전체화면 API도 사용합니다. API가 없거나 브라우저가 거절하면 앱 내부 메뉴만 숨기는 집중 화면으로 동작합니다. 스마트폰에서도 집중 화면에서는 두 영역을 상하로 함께 보여줍니다. 저장 실패 알림은 숨기지 않습니다. 전환 때문에 편집기를 다시 만들지 않으므로 작성한 글·커서·실행 취소를 보존합니다.

2026-11-11 검증: 린트·타입 검사·Pages 빌드, 단위 테스트 20개, 기존/전체화면 Chromium E2E 10개 통과. 클라우드 전용 7개는 이 Pages 검사에서 별도 조건에 따라 건너뛰었습니다. 실제 Safari/iPad의 브라우저 전체화면 동작은 직접 검증하지 못했습니다.
