# 두다다 공부방 · Dudada Study

**PDF를 공부로 바꾸세요.** 병원 소식지·암기노트를 불러와, 필요한 글만 다듬고 한국어로 따라 입력하는 공부방입니다. 계정, 서버 데이터베이스, 유료 API 키가 필요 없습니다.

## 처음 실행하기 (Mac)

1. [Node.js 공식 사이트](https://nodejs.org/ko)에서 **24 LTS**를 설치합니다.
2. 이 저장소를 ZIP으로 다운로드해 압축을 풉니다. Git을 사용한다면 `feat/pdf-typing-practice` 브랜치를 받으세요.
3. Mac의 **터미널**을 열고 `cd `를 입력한 뒤, 압축을 푼 폴더를 터미널로 드래그하고 Enter를 누릅니다.
4. 아래 명령을 한 줄씩 복사해 실행합니다.

```sh
npm ci
npm run dev
```

5. 브라우저에서 `http://localhost:3000`을 엽니다. 종료하려면 터미널에서 Control+C를 누릅니다.

다음부터는 같은 폴더에서 `npm run dev`만 실행하면 됩니다. 첫 설치에는 인터넷이 필요합니다. `npm ci`에서 PDF worker·한글 CMap·표준 폰트·WASM을 같은 사이트의 `public/pdfjs`로 복사합니다. PDF.js 버전과 worker 버전이 항상 일치하며 외부 CDN에 의존하지 않습니다. 파일이 없어졌다면 `npm run postinstall`로 복구합니다.

개발 서버 대신 배포와 같은 방식으로 실행하려면:

```sh
npm run build
npm start
```

## iPad에서 가장 쉽게 사용하기: Vercel 배포

1. GitHub에 코드를 올린 뒤 [Vercel](https://vercel.com)에 GitHub로 가입합니다.
2. **Add New → Project**에서 `dudada` 저장소를 선택합니다.
3. 코드가 있는 브랜치를 선택합니다. 빈 저장소에서 처음 시작했다면 `feat/pdf-typing-practice`를 사용합니다. Framework는 **Next.js**, Root Directory는 저장소 루트입니다.
4. 기본 Install Command(`npm install`)와 Build Command(`npm run build`)를 사용합니다. API 키나 환경변수는 필요 없습니다. Node.js는 24.x를 선택합니다.
5. **Deploy**를 누른 뒤 발급된 HTTPS 주소를 Mac 또는 iPad Safari에서 엽니다. iPad의 공유 메뉴 → **홈 화면에 추가**로 편리하게 접근할 수 있습니다.

이 작업에서 Vercel 배포나 클라우드 환경 게시를 자동으로 수행하지 않습니다. 서버로 PDF를 보내는 API는 없습니다. Vercel에는 앱 코드·정적 PDF.js 자산만 올라갑니다.

## 공부하는 방법

1. **PDF 불러오기** 또는 드래그 앤 드롭으로 파일을 선택합니다. TXT(UTF-8)나 텍스트 붙여넣기도 가능합니다.
2. 페이지 수를 확인하고 추출할 범위를 입력합니다. 예: `1-8`, `3`, `1-3, 5`.
3. 신문형 문서는 **2~5단 · 왼쪽부터**를 선택하고 글자를 추출합니다. 기본은 위에서 아래로 행 순서입니다.
4. 편집 화면에서 **3페이지**를 선택합니다. 원본과 추출 글을 비교하고 잘못된 순서를 수정합니다. 단 정렬을 다시 적용하면 해당 페이지의 편집 내용이 원래 추출 글자로 덮어써집니다.
5. 연구 기사 부분을 텍스트 편집기에서 드래그한 뒤 **선택한 글만 새 자료로 만들기**를 누릅니다. 원문 페이지 번호는 유지됩니다.
6. 제목을 정하고 **타자연습 시작**을 누릅니다. 글과 진도는 입력할 때 자동으로 저장됩니다.
7. 초록색은 일치한 글자, 빨간 밑줄은 다른 글자입니다. Backspace로 수정할 수 있습니다. 정확히 완성하면 자동 이동합니다. **자동 다음 문장**을 끄면 직접 다음으로 이동합니다.
8. 종료하면 오늘 기록과 오답 목록을 확인할 수 있습니다. 오답 재연습은 오타가 있었던 문장을 새로 연습합니다.
9. 다시 접속하면 홈의 **이어서 공부하기**를 누릅니다. 마지막 문장과 입력 중이던 글도 복원됩니다.

### 편집과 모드

- 페이지별 수정, 줄바꿈·공백 정리, 여러 페이지의 반복 머리말/꼬리말 문구 삭제, 빈 줄 기준 문단 순서 변경을 제공합니다.
- **정확히 따라 치기**: 원문의 줄을 단위로 사용하고, 내부 공백·숫자·괄호·영문을 그대로 비교합니다. 줄 끝 Enter는 입력하지 않습니다.
- **공부하기 편한 모드**: 줄바꿈과 공백을 정리하고 문장부호 기준으로 나눕니다.
- 두 모드 모두 장문은 최대 160자로 나눠 보여줍니다. 원문을 AI로 보충하지 않습니다.
- 편집으로 원문이 달라지면 기존 문장별 학습기록을 초기화합니다. 기존 기록을 보존하려면 먼저 선택한 글로 새 자료를 만드세요.
- 정확도 = 현재 입력 중 같은 위치에서 일치하는 글자 / 현재 입력한 글자. 오타를 수정하면 정확도가 회복됩니다. 오답 목록은 수정 전 오타도 기억합니다.
- CPM = 일치하는 글자 수 / 활성 입력 시간(분). 한글은 NFC로 정규화한 완성 글자를 기준으로 셉니다. IME 조합 중인 글자는 비교·오타 기록에서 제외됩니다. 붙여넣기를 차단하는 시험용 서비스는 아닙니다.
- 결과는 **현재 자료의 오늘 기록**입니다. 날짜는 기기 현지 날짜 기준입니다. 평균 속도는 현재 남아 있는 문장 기록의 글자 수/시간으로 계산하며, 재입력한 이전 시도의 속도까지 합산하는 장기 통계는 아닙니다.

## 개인정보와 저장

- PDF는 브라우저의 PDF.js worker에서 처리합니다. PDF/붙여넣은 글의 자동 업로드, 분석 서비스, AI 호출이 없습니다.
- IndexedDB에 제목, 수정된 페이지 텍스트, 원문 페이지 번호, 선택한 페이지, 모드, 문장별 입력·완료·오타 횟수·시간, 마지막 문장·학습 날짜를 저장합니다.
- **원본 PDF, 암호는 저장하지 않습니다.** 재접속 후 원본 미리보기가 필요하면 같은 PDF를 다시 선택하세요. 텍스트와 진도는 다시 추출할 필요가 없습니다.
- 같은 브라우저·같은 사이트 주소에서만 복원됩니다. Mac과 iPad 간 자동 동기화는 없습니다. 비공개 모드나 브라우저 데이터 삭제 시 자료가 사라질 수 있습니다. 중요한 편집 글은 **텍스트 내려받기**로 별도 보관하세요.
- 자료 카드의 휴지통은 자료와 기록을 삭제합니다. 연습 화면의 **학습기록 초기화**는 글을 남기고 기록만 지웁니다.
- 사용자 PDF/TXT와 `.env`는 `.gitignore`로 제외합니다. 테스트 PDF는 사용자 자료가 아니라 테스트 실행 중 생성하는 합성 문서입니다.

## 큰 PDF / 문제 해결

- **100MB 이상**: 경고 후 사용 가능합니다. 다른 탭을 닫고 필요한 페이지만 추출하세요. 페이지를 순차 처리하고 진행률·취소를 제공합니다. 미리보기는 현재 페이지만, 최대 750px 너비로 렌더링합니다.
- 파일은 Blob URL로 열지만 PDF.js/브라우저가 내부적으로 전체 바이트를 읽을 수 있습니다. 범위 선택이 파일 읽기 메모리를 완전히 없애지는 않습니다. **512MB 초과**는 메모리 보호를 위해 거절합니다. 메모리 부족으로 브라우저 탭 자체가 종료되는 상황은 앱에서 복구를 보장할 수 없습니다. 파일을 작은 묶음으로 나눠 재시도하세요.
- **암호 PDF**: 암호 입력란에 입력하고 **파일 다시 열기**를 누릅니다. 앱은 암호를 보관하지 않습니다.
- **손상 PDF**: 원본을 다시 다운로드하거나 PDF 뷰어에서 새 PDF로 저장 후 재시도하세요.
- **스캔 PDF**: “이 PDF는 이미지로 구성되어 있어 글자 인식(OCR)이 필요합니다”라고 안내합니다. OCR 버튼은 비활성화했습니다. 기기에서 인식한 글을 붙여넣거나 직접 입력하세요.
- **글 순서가 섞임**: 2~5단을 선택하고 원본과 비교하세요. 현재 알고리즘은 페이지 폭을 같은 너비의 단으로 나누는 기본 휴리스틱입니다. 큰 제목·단을 가로지르는 사진·서로 다른 단 너비·여러 기사의 경계는 자동으로 완벽히 판별하지 못합니다. 수동 편집이 필요합니다.
- **저장 실패**: 저장 공간을 확보하거나 브라우저의 사이트 저장소 차단을 해제하세요. 화면을 닫기 전에 텍스트를 내려받으세요.
- **worker 오류**: `npm ci` 또는 `npm run postinstall` 후 재시작하세요. `public/pdfjs` 폴더를 배포에서 제외하지 마세요.

## 개발 및 테스트

기술: Next.js App Router, React, TypeScript, Tailwind CSS 4, PDF.js, idb(IndexedDB), Lucide. Node 24 권장. npm lockfile을 포함합니다.

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build

# Chrome 계열 E2E (Linux 환경에 /usr/bin/chromium이 있을 때)
npm run test:e2e -- --project=chromium
```

다른 OS에서는 먼저 `npx playwright install chromium`을 실행합니다. 시스템 Chromium이 없으면 Playwright가 설치한 브라우저를 사용합니다. 다른 실행 파일을 지정하려면 `CHROMIUM_PATH`를 설정하세요.

```sh
# WebKit을 설치할 수 있는 환경에서 iPad 크기 모사 테스트
npx playwright install --with-deps webkit
npm run test:e2e -- --project=webkit
```

Vitest는 정규화·정확도·문장 분리·페이지 범위·CPM·다단 순서·장문 보존을 검사합니다. Playwright는 8페이지 PDF, 한글 파일명, 편집/부분 선택, 원문 미리보기, IME 이벤트, 숫자/약어, 오타 수정, 새로고침 복원, 오답, TXT/모바일 화면, 빈 PDF/손상 PDF, 암호 재입력, 100MB 이상 합성 PDF를 검사합니다.

테스트에서 IME 이벤트를 합성하는 것은 macOS/iPad의 실제 두벌식 입력기 검증을 대신하지 않습니다. 실제 Safari와 iPad 키보드에서의 최종 사용성 검증이 별도로 필요합니다. 이 환경에서는 WebKit 다운로드 도메인이 차단돼 WebKit 검사를 실행하지 못했습니다. 실제 연세의료원소식 PDF는 제공받지 않아 해당 문서 자체에 대한 읽기 순서는 확인하지 않았습니다.

## 구현 범위와 후속 작업

**구현**: 홈/편집/연습/결과 화면, PDF 선택·드롭, 진행률·취소, 페이지 범위, 원본 미리보기, 기본 다단 정렬, 편집/문단 이동/일부 선택, TXT/붙여넣기, 한국어 IME 처리, 두 연습 모드·오답, 속도/정확도/진도, IndexedDB 자동 저장·복원·삭제·초기화, 다크 모드, 글씨 크기, 반응형·키보드 포커스 표시.

**미구현/제한**: Tesseract 한국어+영어 선택 페이지 OCR, 자동 기사 영역 탐지·가변 너비 단 판별, 기기 간 동기화, 원본 PDF 영구 저장, 계정, 장기 시도별 통계, 실제 Safari/iPad 실기기 검증. OCR은 안정성과 메모리를 고려해 자동 실행하지 않으며 후속 기능으로 분리했습니다.

주요 파일:

- `app/study-app.tsx`: 자료 불러오기·편집·서재
- `app/typing.tsx`: 타자연습·IME·결과
- `app/pdf-preview.tsx`: 원본 페이지 렌더링
- `lib/pdf.ts`: PDF 동적 로딩·추출·기본 읽기 순서
- `lib/study.ts`: 문장·정규화·통계·모델
- `lib/storage.ts`: IndexedDB 저장
- `tests/`: 단위 테스트와 E2E
